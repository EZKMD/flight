# flight v0.2.0

v0.2.0 expands the single-flight terminal experience with two responsive visual
modes and optional geographic route context while preserving the established
provider and data-trust semantics.

## New

- Session-only `AltitudeProfileVisual` built from authoritative observations
- Responsive `RouteMapVisual` using sampled great-circle geometry
- Optional Natural Earth coastline layer toggled with `g` inside Route view
- Direction-aware route annotation using the local projected route tangent
- Authoritative `◆` route-position marker for trusted live position or confirmed landing
- Responsive Braille maps with compact and tiny compatibility fallbacks
- `NO_COLOR` support for structurally distinct monochrome rendering

## Improved

- `v` now cycles Aircraft → Altitude → Route → Aircraft
- Route position semantics explicitly distinguish live geospatial progress from
  schedule-time estimates
- Provider-neutral telemetry history supports the altitude profile without
  changing provider refresh cadence
- Projected coastline caching keeps heartbeat and geography-toggle frames lightweight
- Geography preference survives visual switching during the current session

## Data and rendering

- Geography uses Natural Earth 1:110m coastline data pinned to v5.1.2
- The public-domain coastline is generated into a static compiled C artifact
- Route mode uses no runtime GIS library, map API, extra credential, or additional
  network request
- Geography on and off share one viewport, so the route, endpoints, and position
  remain stationary during toggling

## Controls

- `v` cycles Aircraft → Altitude → Route
- `g` toggles geography while Route is active
- `q`, `r`, and fixture-mode `f` retain their existing behavior

## Known limitations

- Geography is intentionally low-detail and the route-local projection can distort
  at high latitudes
- There is no pan/zoom, flown route trail, weather, nearby traffic, waypoint layer,
  or airport board
- OpenSky coverage can remain absent or intermittent, and route position is shown
  only when its existing trust requirements are satisfied
